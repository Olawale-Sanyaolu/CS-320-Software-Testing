# CS-320-Software-Testing
CS 320 Software Testing, Automation, and Quality Assurance Portfolio

## Reflection
### How can I ensure that my code, program, or software is functional and secure?

I can ensure that my software is functional and secure by carefully reviewing the requirements and creating tests that verify that each requirement is met. During this course, I learned how important unit testing is for identifying errors before software is released. In Project One, I created JUnit tests for the Contact, Task, and Appointment services and tested requirements such as valid IDs, field lengths, null values, duplicate IDs, and other input restrictions. I also learned to test both valid and invalid inputs instead of only checking whether the program works under normal conditions. Using automated testing, boundary value analysis, input validation, and secure coding practices can help improve software quality and reduce the possibility of defects or vulnerabilities.

### How do I interpret user needs and incorporate them into a program?
I interpret user needs by first reviewing the requirements and determining exactly what the program is expected to accomplish. I then translate those requirements into specific program behaviors and testable conditions. For example, the Contact Service included requirements for contact IDs, names, phone numbers, and addresses. Each requirement had specific restrictions that needed to be implemented in the code and verified through unit testing. Breaking requirements into smaller pieces helped me understand what needed to be developed and how I could confirm that the program met the user's expectations. I learned that it is important not to make assumptions about requirements because even a small misunderstanding can result in software that does not meet the customer's needs.

### How do I approach designing software?

I approach software design by first understanding the requirements and then dividing the program into smaller, manageable components. I consider what each class or service is responsible for and how the components will work together. I also think about testing while developing the software instead of waiting until development is finished. In CS 320, creating and testing the Contact, Task, and Appointment services showed me how separating responsibilities can make software easier to develop, test, and maintain. I use unit tests to verify individual components and compare the results against the original requirements. Going forward, I will continue using a structured approach that includes understanding requirements, designing manageable components, implementing the code, testing different conditions, and improving the software when problems are discovered.
